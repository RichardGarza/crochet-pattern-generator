## Public API

### `src/state/slices/model3d.ts`

All edits are pure: they never mutate their input, return the input itself when nothing changes, keep untouched
parts as the same objects, and round derived coordinates to 1e-6 (`roundCoord`). Lengths in inches.

| Export | Signature | What it does |
|---|---|---|

| `Pivot` | `{ center: Vec3; rotationDeg: Vec3 }` | The gizmo's pivot: a part's center (§0.1) and rotation |
| `SNAP_MOVE_IN`, `SNAP_ROTATE_DEG`, `SNAP_DIM_IN`, `REANCHOR_INTERVAL_MS` | `0.05`, `5`, `0.05`, `100` | §4.2 |

| `transformPart` | `(model, partId, m: Rigid, scope = 'subtree') => model` | `m` applied to the part (and its subtree) |
| `movePart` | `(model, partId, delta: Vec3, scope = 'subtree') => model` | Move by `delta` |
| `rotationAbout` | `(center: Vec3, rotationDeg: Vec3) => Rigid` | Rotation about a world point |
| `transformByPivot` | `(model, partId, from: Pivot, to: Pivot, scope = 'subtree') => model` | The gizmo drag: `m = to · from⁻¹` |
| `pivotOf` | `(part: Part) => Pivot` | `partCenter` + rotation |

| `setPartColor` | `(model, partId, color) => model` | Palette ids only |
| `setPartLabel` | `(model, partId, label) => model` | Trimmed; empty removes the label |

## Deviations (with reasons)

1. **Round sizes are shown as diameters** ("Width" = 2·rx, "Diameter" = 2·r, "Ring diameter", "Tube thickness"):
   crocheters measure across a piece. The model keeps radii (§3.5.1); the fields convert.
2. **Resize (gizmo) keeps the part's CENTER fixed** (the gizmo's pivot; a lathe's origin moves), while Parameters
   (inspector fields) keep the part's `position` (its origin, §0.1: a lathe's base). §4.2 does not say which.
3. **"Attached parts follow" toggle** (on by default) next to the tools; ⌥ inverts it for one drag. §4.2 has only
   ⌥; the toggle makes the "part alone" edit reachable from the keyboard and the inspector's fields (which have no
   drag to hold ⌥ on). Inspector position / rotation edits follow the same rule as the gizmo.
4. **Snapping while resizing** rounds the dims that changed to the 0.05 in grid (§4.2 names 0.05 in / 5° for the
   gizmos without saying how Scale snaps).
5. **Resize of mesh parts is disabled** with a reason (baking into the vertex buffer needs the mesh-asset
   plumbing of T6.4); the viewport gets `meshes = {}` until mesh assets are decoded (T6.4), so a mesh part is drawn
   as the builder's `bboxIn` ellipsoid.
6. **`revision` + 1 per editor history step** (§3.5.1 "+1 on every edit"); a drag bumps it once.
7. **Mirror-linked twins do not follow drags yet** — "linked edits propagate" belongs to the Mirror tool (T6.2).
8. **Sample teddy** in the empty state ("Try the sample teddy"), as the brief asks for the fixture as the demo
   model; it enters as a model revision (`source: 'import'`, one undo step).
9. **The viewport talks to `editorStore` and the slice directly**: the frozen `ViewportProps` has no gizmo or
   camera callbacks; a stub `Viewport` simply ignores them.
10. **Re-anchoring of the Inspector's size SLIDER is throttled like the gizmo** (`beginResizeGesture`, 10 Hz): the
    slider is a drag too.
11. **Dims edits always leave a valid model** (§3.5.2), also at extremes: a capsule is never shorter than two caps of
    the smallest radius (0.1 in); a lathe profile's largest radius and its height are kept in [0.05, 48] by scaling
    the radii / heights (shape kept); a polygon flat's `points` follow its width and height, and other flat shapes
    drop `points`; a sphere whose snapped radii come out equal stays a sphere. Lathe radii are not snapped.
12. **Escape during a gizmo drag cancels it** (no history step, the part goes back); Escape otherwise clears the
    selection. Q/W/E/R do nothing on a read-only project.
13. **A hint on the view** when the active tool cannot act ("Select a part to move it", or why a sculpted part
    cannot be resized).

## Ambiguities resolved

| Where | Reading |
|---|---|
| §4.1 camera "Left" | The toy's own left side: camera at +X (as §2.9.2's photo views); Top = camera at +Y with the front at the bottom |
| §4.2 gizmo space | Move and Rotate in world axes, Resize in the part's own axes (three.js `TransformControls` always scales locally) |
| §4.2 "click empty deselects" | A click that ends an orbit drag (pointer moved > 4 px) or a gizmo drag (within 250 ms) changes nothing |
| §4.2 "Shift adds" | ⇧-click toggles a part in or out; the last part added is the primary (gizmo, inspector) |
| `W_GAP` in the editor | Computed live from `surfaceGap` > 0.1 in for every attached part; shown in the outliner, the inspector and the status bar |

## Known limits

1. `TransformControls` points an axis arrow toward the camera, so in the Front view a part above the camera shows
   its Y arrow pointing down (three.js behavior).
2. Only Escape interrupts a gizmo drag; `TransformControls` keeps its own drag state until the pointer is released.

## Independent review (T6.1)

A separate agent reviewed the code against §4.1–§4.4 and §6.3 T6, fuzzed the slice (NaN, zero/negative factors,
extreme dims, cycles, every part type of `every-type.json`), measured WebGL resources, walked the keyboard and
measured contrast in the running app. Findings and outcome:

| Finding | Severity | Outcome |
|---|---|---|
| `ContactShadows` remounted on every edit (keyed); drei never frees its render targets: +56 textures/framebuffers per drag | blocker | always mounted, size in powers of two, off = hidden and not rendered; measured: 30 resizes → live textures 13 → 13, framebuffers 14 → 14 |
| A gizmo Move rewrote Euler angles (deg → rad → deg noise sent it down the rotation path: `[0,180,0]` → `[-180,0,-180]`) | major | rotations compared as matrices (1e-9); test with three's radian noise |
| Capsule length below 0.1 in gave r < 0.05 (schema-invalid) | major | capsule floor 2 × 0.05; test |
| Lathe resize unclamped (radius/height outside [0.05, 48]) | major | `normalizeDims` keeps both in range; "every edit of every part type stays valid" test over `every-type.json` (5 scale vectors × snap × every part, every dim at 0 / 0.01 / 0.07 / 1000 / −3) |
| Escape during a drag committed it | minor | cancels (`editorStore.cancelDrag`); e2e |
| Polygon flats ignored w/h; stale points after a shape change | minor | points scaled; dropped for other shapes; test |
| Sphere → equal-radii ellipsoid after a tiny drag with snapping | minor | decided after snapping; test |
| Negative / zero scale factor snapped the part back | minor | factors ≥ 0.01 |
| Position fields clipped at 1100 px | minor | X/Y/Z wrap to two rows below 3 × 76 px |
| Help text 4.21:1 | minor | `--color-text-muted` |
| Camera pill over the model's top | minor | fit margin 1.12 and the target raised by 0.06 × radius |
| No feedback for Resize on a mesh part / tools with nothing selected | minor | hint on the view |
| Slider names "Width slider"; ←/→ in the tree did not select | minor | sliders named like their field; ←/→ select the row they move to |
| e2e ⌥-drag did not assert the flag | minor | asserts "Head, has a gap to its parent" |
| No e2e for the Rotate gizmo | minor | not done: the rings are hard to grab reliably by coordinates; Rotate is covered by unit tests of `transformByPivot` / `setPartRotation` and the gizmo shares Move's code path |
| Grammar, unread `dragging`, tool keys on read-only, cursor left as pointer, profile row keys, header comment, "Turned shape" | nit | fixed ("Shaped round") |
| Reframe key (name + first part id) misses a new model with the same name and root | nit | kept: a new revision of the same toy keeps the camera, which is wanted |
| Icon reuse (grid / sun / layers) | nit | kept until the S0 icon lane adds 3D icons |
