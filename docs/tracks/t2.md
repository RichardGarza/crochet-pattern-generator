## Line-model conventions (T2.2)

- **Border:** `kind: 'border'`; Rnd 1 `start: { k: 'edge' }`, `side: 'RS'`, `arrow` = the start corner (pointing at
  it), ops `inc3` + S − 2 sc per edge from the start corner, `join: {}`, and the color cue `join B` when it is
  joined (no cue = continued from the last stitch). Rnds 2–n `start: { k: 'join' }`, `join: {}`, no side. The
  arrow and cue are not printed; the opening sentence says both.
- **Block repeat:** the note `Rows 13–24: rep Rows 1–12.` (`… 2 times.`) in `notes` of the block's last line; the
  repeated lines are not in `Piece.lines`.
- **Tapestry cues:** `join B`, `carry A, B`, `cut C` (color cues). **C2C cues:** `join B (bobbin n)`.
- **Pieces:** one piece `panel` (title "Panel", "Tube" for tapestry in the round): the technique's lines, then the
  border rounds; `finish.text` "Fasten off and weave in ends."

## The verbose dialect (what T2.1 prints; T2.2: with the reading arrow)

Rows and rounds of a chart (`docKind '2d'`): the label with its reading arrow, as compact (T2.2; T2.1 left it out); color
runs as `With A, sc in first 4 sts; change to B, sc in next 3 sts; change to A, sc in last 33 sts.`; Row 1
`With A, sc in 2nd ch from hook and in next ch; …` (one color: `sc in 2nd ch from hook and in each ch across`);
count `(40 sc)` when every op is the same plain stitch, else `(N sts)`; color cues after the count as in compact.
Amigurumi rounds (`'3d'`): research 07 §7.5 — `sc in next N sts`, `2 sc in each of next N sts`, `invdec` /
`sc2tog` (`invdec 3 times`), `sc in back loop only of next N sts`, `Working in back loops only, …` for a BLO round,
`[A, B] n times`, `with A, …` (inside brackets every color names itself), `(18 sts)`; MR `6 sc in MR`; the joined
round `Ch 1 (does not count), sc in same st as join, …; join with sl st in first sc.`. C2C rows: the first tile
from the row's start (`ch 6, dc in 4th ch from hook and in next 2 ch` / `sl st in next 3 dc and in ch-3 sp, ch 3,
3 dc in same sp`), then `(sl st, ch 3, 3 dc) in next ch-3 sp`, and `sl st in last ch-3 sp, turn` for a decrease at
the end.

## Deviations from the spec, with reasons

1. **`renderLine` ignores `hand`.** A left-handed chart pattern differs from the right-handed one in more than the
   order of each row: the foundation color (first run in working order), the corner a border starts in (§2.7.10),
   C2C bobbins (6-connectivity on the transformed chart), the pre-skew direction of tapestry rounds (§2.7.5) and the
   bobbin numbering. So the writers generate lines for `settings.hand` (`PatternDoc.hand`) and the renderer prints
   them as written. A view that wants the other hand rebuilds the doc. Request 2.
2. *(Resolved in T2.2: verbose lines print the reading arrow, §2.7.2 v1.4.)* The verbose dialect prints the color
   cues after the count as compact does.
3. **G9 is matched with the writer's `cues: false`.** By §2.7.3 the writer prints `· join B (bobbin n)` for new
   strands and `· carry A` for carried colors, and G9's chart has both (Row 1 joins B and carries A across it; Row
   2 carries A). The §2.7.3 golden shows the bare rows; the template marks the cues optional. Default output is
   `Row 1 (RS) ←: Starting in 2nd ch from hook, 2 sc A, sc B, 2 sc A (5 sts) · join B (bobbin 1) · carry A`; both
   are tested. Request 3.
4. **Amigurumi notes define `N op` for every op** (`“N sc” = sc in each of the next N sts, and likewise for every
   stitch (“3 inc” = inc in each of the next 3 sts)`), because the kernel prints `3 inc` (s0b request 4).
5. **Flat-graph notes** add the row-boundary rule of §2.7.2 ("Stated once in Notes") and a one-line legend of the
   two cues; the reading sentence is written for the pattern's hand (`… (left-handed: reverse)` / `… (right-handed:
   reverse)`).
6. *(Resolved in T2.2: `decMethod` added; without it both decreases are listed, as before.)*
7. **`> 6 strands in a row` is `W_ROW_COLORS`** (the per-line caps of §2.4.3 are the only description of that
   code). Request 4.
8. **`E_RUN_SUM` also reports rows that do not cover the chart** (a missing row sums to 0 ≠ W; a repeated or extra
   row is reported the same way) **and rows that are not their chart row** (read in the pattern hand's direction,
   with the right side and arrow), since no other code covers them; a wrong turning chain is `E_FOUNDATION`
   (`W + h_tc − c` names `h_tc`). A chart round without side and arrow is `E_SANITY`, because `renderLine` would
   print it as an amigurumi round (request 1).
9. **`computeSkill` bands for non-integer means:** ≤ 2 → 0, (2, 6] → 1, > 6 → 2 (the table says 3–6); the reason
   prints the mean rounded up to 0.1 so it never reads as the band edge. A flat or round chart with no color change
   inside its lines counts as stripes (0 technique points); `amigurumi_sc` and an input without a technique have no
   technique points.

T2.2:

10. **The border's start corner and join live in Rnd 1's `arrow` and a `join B` cue** (see Line-model conventions):
    the frozen `Line` has no field for them, and `E_BORDER` must check "Rnd 1 opens at the corner where the last
    line ends or with a join". The border text is generated by T2's renderer from the line; the spacing hints and
    the C2C words need the technique and the panel size, which `renderLine`'s frozen options do not carry
    (`renderLineWith(…, { border: { technique, rows, cols } })` gives the exact §2.7.10 text; plain `renderLine`
    prints the same sentences with row words and no hints). For border lines `renderLine` reads `o.hand` (left /
    right edge names); lines are written for `doc.hand` and callers pass it. Request 12.
11. **Rnds 2–n of a border print as one line only through `renderBorderLines`** (the §2.7.10 fold of lines with
    different counts); `renderLine` prints each round on its own (`Rnd 2: … (620 sts)`), which is still correct.
12. **Per-side border counts are at least 2** (`S = max(2, …)`): a side includes one stitch of each corner group, so
    a 1-stitch or 1-row panel cannot have less; §2.7.10 does not say. An edge with S − 2 = 0 prints no edge phrase.
13. **Spacing hint without a ratio within 4%** (b ≤ 6): `{k} sc over {units} row ends`. Hints print on the first
    vertical edge (rows) and on the first horizontal and first vertical edge (C2C), as the G16/G22 goldens do.
14. **Which borders continue:** sc/hdc graphgan and sc tapestry continue when the border color is the last
    stitch's; C2C always joins (§2.7.10) and so does mosaic (yarn cut every row).
15. **Block repeats** are notes on the block's last line (no `Line` field for them); the first line of a piece is
    never in a block (repeating it would not start from the chain); a block of identical lines is left to folding;
    turned rounds need an even block like flat rows; `applyRepeats` `auto` and `ask` both write repeats (the UI of
    T2.3 will offer `ask`), `off` never. One repeat per piece (§2.6.2 "the longest … becomes"), the one saving most
    lines.
16. **Turned tapestry rounds are never folded** (consecutive rounds alternate sides). Folded rounds keep their side
    and arrow (all rounds of a non-turned tube are RS and read the same way), and `E_SANITY` keeps requiring them.
17. **Tapestry cue words:** `join B` (no bobbin: one ball), `carry A, B` (every held color that is not worked on
    every stitch of the line, worked colors first in working order, then the ones only carried, in palette
    order), `cut C` (none on the last line: the piece is fastened off). The foundation color is not joined.
18. **C2C rows print `join B (bobbin n)` where a new region starts** (§2.7.6 prints no cues; `cues: false` gives
    the golden text, as G9). The phase note: "One side now has its full length: …" (W ≠ H) or "The piece now has
    its full width: …" (W = H).
19. **Yardage details §2.8 leaves open:** a tapestry tube's ring (ch C + sl st) and each round's ch 1 + joining
    sl st are charged to the round's first color; turning chains to their row's first color; C2C has no extra
    chains (inside the 7.76 L tile). `MaterialsLine.strands` = bobbins to wind (graphgan `bobbinsPerColor`, C2C the
    most regions in use at once, tapestry 1). Grams only when the yarn gives yd/100 g or its skein; skeins only
    when it gives the skein length (`buildPattern2D` has no CYC to fall back on).
20. **Border color:** unset → palette `A` (or the first entry); a `ColorRef` with a yarn id or hex of the chart →
    that color; otherwise a new code (next free letter) with its own Materials line, accepted by `E_COLOR` through
    `extraCodes` (and `doc.materials` in `validateDoc2D`).
21. **`validateDoc2D` without settings infers** the tapestry lean (turn if a round turns; pre-skew with a rate
    found by intersecting the shift intervals of every round, |rate| ≤ 8; else note) and the C2C corner (Row 1's
    arrow), and checks the border without the gauge (opposite sides equal, `S_top = W` for rows). T8's pre-export
    check should pass the project's settings and gauge (request 18).
22. **`mosaic_overlay`:** `buildPattern2D` returns a doc with no piece and one `E_SANITY` ("not written yet") until
    T2.4. `hdc_graphgan` (P1) is built (its writer was done in T2.1).
23. **The doc hash** covers non-integer numbers as 6-decimal strings and lines by their run-length keys (§5.8
    "never raw floats"; hashing the canonical JSON of a 1000 × 1000 doc took 4.5 s, the streamed hash 0.2 s).

## Ambiguities resolved

| Where | Reading |
|---|---|
| §2.7.2 compact example `· carry B` | A format example. By §2.7.3 the color absent for ≤ 8 sts and coming back is carried, so on that row the cue is `carry A` (A is carried across the 3 B sts). |
| §2.7.3 strand continuation | A row's runs of one color joined by carries form a segment (one strand). A segment continues a strand of the previous row when one of its runs, widened by 2, overlaps a run of that strand's segment there; one-to-one, greedily in working order, largest overlap first; a strand not continued ends. Row 1's first segment is the foundation strand. A new strand takes the lowest bobbin number of its color not in use in that row, so `bobbin n` never exceeds the bobbins to wind (Materials: `bobbinsPerColor`); `strandsPerColor` counts every strand started (tails). |
| §2.7.3 cue order | `join …` cues (one per new strand, working order), then one `carry A, C` cue (colors in working order). |
| §2.6.2 folding of rows | Consecutive rows fold when their ops are identical **and** a palindrome (direction-independent) **and** their cues are identical; never Row 1; the fold drops side and arrow. Mirrored zig-zag rows (same ops, not palindromes) are not folded. |
| `E_FOLD` | Checked by T2 for flat rows: each row in the range, read from the chart in its own direction, must equal the line's ops, its plan cues must equal the line's color cues (skipped when the pattern prints no strand cues), the ops must be a palindrome, no side/arrow, not Row 1. |
| `E_FOUNDATION` vs the kernel | The kernel reports a Row 1 that does not use `chains − firstInto + 1` chains; T2 reports a foundation that is not `W + h_tc` from the `(h + 1)`th ch, and does not repeat the kernel's issue on the same line. |
| 2D `E_SANITY` | Chart sides 1–1000, one label per cell, a palette. R15's 20 000 sts per piece is not applied to a chart (G2's 135 × 200 has 27 000). |
| `NotesForFn` ctx `corner` | Accepts `BR/BL/TR/TL` or words; default BR (RH) / BL (LH) (§2.7.6). Arrows default from the corner and hand. |
| Tapestry lean without R | `notesFor` has no round count, so it prints the drift per round (`about 0.5 st per round to the right`); `notesWith(…, { rounds })` prints the §2.7.5 sentence with `round(stPerRnd·(R − 1))`. |
| §2.7.5 pre-skew direction | "Rotated by s_k sts in the working direction": working position i takes the color the unskewed round has at i − s_k (circularly). The finished stitches drift s_k against the working direction, so each lands where the chart shows it. Same rule for both hands in working order; negative rates shift the other way. |
| §2.7.4 "carried" | A color is carried in a line when it is held (joined, not yet cut) and at least one stitch of the line is another color; a held color absent from the line is carried across all of it. |
| §2.7.10 corner phrases | The bottom corner reached after working down a side is "the corner loop of the foundation ch (bottom left/right)", the other "the last loop (bottom … corner)"; for C2C every corner is "the outer corner of the … tile". |
| §2.6.2 equal lines | Two lines are the same line for a block repeat when everything but their number is equal (ops, start, side, arrow, cues, join, notes, counts). |
| C2C bobbin numbers | Like strands: a region holds its number from its first to its last row; a new region takes the lowest free number of its color, so the highest number is the bobbins to wind; every region has 2 tails. |
| UK free text | `toTerms` converts CYC's table (incl. gauge→tension, yo→yoh, yarn over→yarn over hook) and the decrease ladder; it does not change spelling (color/colour) or `skip` (unverified, research 07 §1.3). |
