### How the types were checked

`scripts/check-spec-types.mjs` cuts the four TypeScript blocks of the spec (§3.5.1, §3.7.1, §5.2, §5.2.1) out of
`DESIGN.md` verbatim and asks the compiler whether every declaration in them is **identical** to its counterpart
in `src/types` (`(<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2)`), not merely
assignable: 134 declarations. A changed optional marker three levels deep, or a removed union member, fails it
and names the declarations that differ. It runs on demand (`node scripts/check-spec-types.mjs`) and as a unit
test, so the frozen types cannot drift from the spec unnoticed and an S0 amendment has to change both
together. Deliberate differences are listed in the script as `PENDING_SPEC_AMENDMENTS`; there is one
(`ProjectDoc.threeD.model`, below).

`src/types/__checks__/entryPoints.check.ts` guards the other side: `npm run typecheck` fails when a function at
a track-owned path no longer has exactly its frozen signature (identical parameters and result; a stub passes;
`any`, a dropped optional parameter or a widened result do not). 0c can add the 0b modules to it.

  `hexToLinearRgb`, `linearRgbToHex`; OKLab: `linearRgbToOklab`, `oklabToLinearRgb`, `srgb8ToOklab`,
  `hexToOklab`, `oklabToHex`; D4: `toe`, `toeInv`, `oklabToFeature`, `featureToOklab`, `srgb8ToFeature`,

  `seed32`), `fnv1a32`, `canonicalJson`, `CODE_VERSION`. The hashers take a string, bytes or any typed array
  (hashed as the bytes it holds); a plain array must hold byte values or they throw.
- `prng.ts` — `mulberry32`, `randomInt`, `randomRange`, `shuffle`. Type `Rng`.
- `stable.ts` — `stableSort`, `stableSortInPlace`, `argsort` (returns `number[]`), `argmin`, `argmax`.

- `stub.ts` — `NotImplementedError`, `stub`, `isImplemented`, `isNotImplementedError`.

Verification beyond the unit tests: CIEDE2000, OKLab and CIELAB were compared with culori 4 in a scratch folder
(random Lab pairs agree to 2e-13; random sRGB colors to 4e-8 in OKLab and 1e-13 in Lab); mulberry32 and both
FNV hashes are tested against BigInt reference implementations; the PNG decoder was run against an independent
writer for every color type, depth and filter. Two independent review passes read the kernels, types, scripts
and configuration; what they found is fixed, and what is a decision rather than a fix is listed below.

## Deviations from the spec, with reasons

1. **Wrong-Node failure message.** With `devEngines.runtime.onFail: "error"` (§5.6), npm ≥ 10.9 stops before
   any script runs, so under Node 20.18 `npm test` exits 1 with npm's `EBADDEVENGINES` text, not with the
   check-node text that the §6.2 acceptance line names. `scripts/check-node.mjs` itself exits 1 with the nvm
   one-liner under Node 20.18 and is what fires on an npm that does not know `devEngines`. The explicit
   configuration of §5.6 was kept.
2. **tsconfig.** Room-planner's settings plus `"strict": true`, and three additions that later tracks need and
   cannot make themselves: `"types": ["vite/client", "node"]` (tests read fixtures with `node:fs`; the manifold
   loader of §5.4 reads `process`), `"resolveJsonModule": true` (yarn data and templates are JSON), and in
   `tsconfig.node.json` `module: esnext` + `moduleResolution: bundler` + the DOM lib + `jsx` instead of
   `nodenext`: `scripts/*.ts` and `e2e/**` import modules from `src/`, whose extension-less imports do not
   type-check under `nodenext`. `tsconfig.node.json` also covers `playwright.config.ts`, `scripts/**` and `e2e/**`.
   Two consequences of the node types in `src/`: `setTimeout` returns `NodeJS.Timeout` there (write
   `ReturnType<typeof setTimeout>`), and Node-only APIs type-check in code that runs in the browser — the node
   test environment and the e2e tests are what catch those.
3. **Scripts that §5.1 does not list:** `scripts/ports.ts` (the port rules of §5.5.4 as tested functions and a
   Vite plugin, used by `vite.config.ts` and `playwright.config.ts`), `scripts/check-spec-types.mjs` (above) and
   `scripts/image-metadata.mjs` (the metadata scanner shared by `strip-exif.mjs` and the fixture-privacy test).
4. **Ports, stricter than written.** A root under `.claude/worktrees/` never gets 5180, even with
   `CPG_PORT=5180` (5199 instead). A worktree that is not named `t<N>-…` (the Step 0b worktrees, a throw-away
   check) gets a port from its own name — dev 5200–5279, e2e the same + 100 — so several of them can serve at
   once; the spec only defines the main checkout and `t<N>-…`. `CPG_E2E_PORT=5180` is refused.
   `CLAUDE_CODE_CHILD_SESSION` and `CPG_TEST` count as set whenever they are defined, even empty. The
   `portGuard` plugin applies the rule after Vite has merged command-line options, so `vite --port 5180` and
   `--strictPort false` cannot get around it (5180 becomes 5199; `strictPort` is always on).
5. **Vitest block:** `setupFiles: ['./src/test/setup.ts']` was added to the block of §6.2 item 2; without it
   the setup file of §5.1 would never run.
6. **`NotImplementedError`** declares `readonly fn` as a field: a constructor parameter property is not
   erasable syntax. The public shape is the same. (`Superseded` in 0b needs the same.) `core/stub.ts` also
   exports `isNotImplementedError(e)`, which recognizes the error by name after comlink has rebuilt it;
   `isImplemented` is for functions imported in the same thread, not for comlink proxies.
7. **`.gitignore`:** also `*.local`, `*.log`, `/coverage/`; the output folders are anchored to the repository
   root (`/dist/`, `/test-results/`, `/playwright-report/`, `/.cache/`), so a source folder named `dist` or
   `coverage` is not ignored by accident.
8. **PNG codec:** `encodePng` returns `Uint8Array<ArrayBuffer>` (assignable to the frozen `Uint8Array`, and
   usable as a `BlobPart` under TypeScript 6); `decodePng` also reads 1-, 2- and 4-bit gray and palette images
   and applies tRNS.
9. **Fixture-privacy test:** broader than the rule's text. It identifies every file git tracks or would add by
   its magic bytes, fails closed on images it cannot walk, also reports IPTC, comments, unknown application
   segments, PNG text and time chunks and bytes appended after the image, refuses HEIC/TIFF/video containers,
   and looks inside zip, gzip and tar.gz files and base64 data URIs. A C2PA manifest is accepted unless it holds
   Exif, IPTC or author assertions (the committed Claude Design thumbnail carries Anthropic's content
   credentials). Not opened: images inside a GLB, and assets packed into a standalone-HTML bundle.
10. **Plugin stub** `scripts/project-folder.ts` is not a pure no-op: it answers 503 on `/__projects` and 501 on
    `/__convert`. A plugin with no hooks would let Vite's index.html fallback answer 200 to the mirror probe.
    It reads and writes no folder.
11. **Kernel extras** not named in the spec: `canonicalJson`, `CODE_VERSION`, the incremental hasher,
    `fnv1a32` (§2.11.1 seeds `mulberry32(fnv1a(partId))`), `argsort` / `argmin` / `argmax`, `eigenSymmetric3`,
    `randomInt` / `randomRange` / `shuffle`.
12. **Playwright config:** one worker (all specs share one dev server and one projects folder), viewport
    1280 × 800 (§5.7), the HTML report in `playwright-report/`, and the fresh projects folder exported to specs
    as `CPG_E2E_PROJECTS_DIR`.
13. **`src/types`** has four files the spec does not name: `entryPoints.ts`, `ui.ts`, `index.ts`,
    `__checks__/entryPoints.check.ts` (see "Ambiguities").
14. **`scripts/strip-exif.mjs` has a unit test that starts headless Chromium** (about 2 s; skipped where
    Playwright's Chromium is not installed). It was the only way to prove that orientation is applied and GPS
    removed. The script refuses to write over an original even with `--force`, comparing files by identity, so
    a name that differs only in letter case is caught on this case-insensitive disk.
15. **npm:** the lockfile was written with `npx -y npm@11.21.0 install`; npm was not upgraded globally (the
    owner has not been asked). No dependency install script is allowed in `package.json`.
16. **Lint:** `.oxlintrc.json` sets the `correctness` category to `error`. With room-planner's settings every
    finding except `react/rules-of-hooks` was a warning and `npm run lint` passed on a file with `debugger` in it.

No dependency version had to change: every version of §5.6 exists and installs (`vite ^8.3.1` resolved to
8.3.2, `@types/node ^24` to 24.19.0).

## Requests for integration

1. **§5.2 `ProjectDoc.threeD.model`:** make it optional in the spec (first row above), then delete the entry
   from `PENDING_SPEC_AMENDMENTS` in `scripts/check-spec-types.mjs`. If the decision goes the other way —
   `threeD` is created only by the first build or import — the spec has to say where photo views and
   `recon.targetHeightIn` live until then.
2. **Typed arrays, before the freeze:** either keep the bare names and tell every track to cast at DOM and
   transfer boundaries, or change the data-carrying fields (`RgbaImage.data`, `ChartGrid.labels`, `ColoredMesh.*`,
   `SdfVolume.data`, masks, labels, depth, ghosts, ring polylines) to `…<ArrayBuffer>`. The second matches D20
   (there is no SharedArrayBuffer in this app) and removes the casts on the reading side; code that produces the
   arrays from three.js attributes, fflate output or Node buffers then needs the cast or a copy instead. It is a
   one-pass edit of `src/types` plus one more pending amendment in the check script; `decodePng`'s parameter
   should stay a bare `Uint8Array`.
3. **`ChannelLike` and `BroadcastChannel`:** decide between the adapter (above) and a handler type that
   `BroadcastChannel` satisfies.
4. **§6.2 acceptance:** reword "`npm test` under Node 20.18 exits non-zero with the check-node message" to
   "exits non-zero (npm's `EBADDEVENGINES` on npm ≥ 10.9; the check-node message on an npm without
   `devEngines`)" — or change `devEngines.runtime.onFail` to `warn`, which gives the check-node message but lets
   scripts without a pre-hook (`preview`, `schema`, `fixtures`, `cd-fixtures`, `copy-ort`) run on a wrong Node.
5. **§5.1:** list `scripts/ports.ts`, `scripts/check-spec-types.mjs`, `scripts/image-metadata.mjs`,
   `src/types/{entryPoints,ui,index}.ts` and `src/types/__checks__/entryPoints.check.ts` as S0 files. Keep the
   code blocks of §3.5.1, §3.7.1, §5.2 and §5.2.1 compilable: `check-spec-types` reads them.
6. **§6.2 item 2:** record the tsconfig additions of deviation 2, `setupFiles`, the `portGuard` plugin and the
   lint category.
7. **§5.5.4, mirror probe:** Chromium logs a console error for every response with status ≥ 400, so
   `HEAD /__projects` → 503 (the specified "mirror off" answer) trips the "no console errors" rule of the e2e
   specs whenever the mirror is off. At Step 0 that is always (the stub). Either the Step 0 shell does not
   probe, or the smoke spec ignores that one line, or the disabled state answers 204 with a header.
8. **§5.4 / §5.2.1, `latestWins`:** it needs `Q extends { jobId: number }`. Only `Chart2dApi.run`,
   `GeomApi.build`, `GeomApi.projectColors`, `MeshApi.pathB` and `AmiApi.generate` carry a `jobId`;
   `buildPattern`, `mask`, the `MlApi` methods, the other `MeshApi` methods and `importInputs` cannot be
   wrapped as written.
9. **§5.2.1, stubs across workers:** say that `isImplemented` is same-thread only and that a stub's rejection
   from a worker is recognized with `isNotImplementedError` (a comlink proxy answers every property read with
   another proxy, and rebuilds errors as plain `Error`s).
10. **§5.2.1, `useAutosave`:** a throwing stub hook cannot be guarded with `if (isImplemented(…))` inside a
    component (rules of hooks). The stub file shows the module-scope choice to use instead.
11. **§5.6:** npm 11.21 blocks dependency install scripts unless `package.json` lists them under
    `allowScripts`; npm 10 runs them. Five packages have one (esbuild, fsevents, onnxruntime-node, protobufjs,
    core-js) and none is needed (`docs/DEPENDENCIES.md`): all checks pass after a clean `npm ci` with either npm. npm 10's `npm ci` also installs three optional packages that npm 11
    skips (`@img/sharp-wasm32`, `@emnapi/runtime`, `tslib`) and lists them as extraneous in `npm ls`; harmless.
12. **§5.6, licenses:** two optional native libraries of sharp (a dependency of transformers.js and of
    manifold-3d, used only in Node) are LGPL-3.0-or-later. They are not in the browser bundle.
13. **§5.8:** say where `CODE_VERSION` lives (now `src/core/kernel/hash.ts`) and who bumps it.
14. **§6.1 rule 5:** `@playwright/test` cannot be imported inside a Vitest file (both install the global
    `expect` matchers); a test that needs a browser starts a child process, as `scripts/__tests__/strip-exif.test.ts` does.
15. **§6.1 rule 9:** the embedded-image scan of exports is now partly automatic (zip, gzip, tar.gz, data URIs);
    GLB images and standalone-HTML bundles still need the manual look.
16. **§5.2 `ProjectSummary`:** it has no field for the "waiting for Claude Design" badge that §5.7 puts on the
    library cards; `list()` cannot show it without opening every project. An optional field would be an
    additive amendment.
17. **§4.2 `LIMB_TEMPLATE`:** the text gives "arm nubs 0.15 for creatures" but no leg value for `creature`, and no
    arm value for `quadruped-standing`; the type needs both numbers for every row.
18. **Still open for the owner:** OK to run `npm i -g npm@11.21.0` inside the Node 22 install? Without it every
    npm command on npm 10.9.9 prints the `devEngines` warning and the check-node note (both harmless).
