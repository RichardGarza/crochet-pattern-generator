## Deviations from the spec, with reasons

1. **Persistence starts when `useAutosave.ts` is imported** (in a browser with IndexedDB), not from
   `projectSession.ts` as s0c request 1 suggests: `ui/shell` is S0-owned, and the shell's chip switches to
   `useAutosave` by itself the moment the hook is implemented (`saveStatus.ts`), so without the switch the chip
   would claim "Saved" (or "Saving…" forever) over a memory backend. Consequence: **`e2e/smoke.spec.ts:95`
   expects "Not saved yet" and now sees "Saved"** (5 card tests). With that one assertion changed to `'Saved'`
   the whole e2e suite passes (19/19, checked and reverted — `e2e/**` is integration-owned). See request 1.
2. **Take over bumps the stored rev** (and snapshots the document first). §5.5.2 says the old holder's later
   save "is caught by compare-and-swap"; without the bump, the old holder's FIRST save after a steal would
   succeed (same rev) and the taker's next save would become the copy instead. With the bump the outcome is
   deterministic: whatever the old holder still saves becomes a copy (the acceptance wording).
3. **"Edit here instead" protocol**: `release {id, from}` → the holder flushes (≤ 4 s), lets go, waits until the
   lock manager confirms, then posts `released {id, to}`; the asker retries `ifAvailable` every 100 ms until the
   5 s deadline (Chromium can report the release a moment after the message). A hand-over that arrives after the
   timeout still gives the asker the lock (`lock-acquired`): the user asked for it. The asker never queues a
   blocking lock request, because `LockManagerLike` has no `signal` to cancel one.
4. **`useAutosave().status` maps `unsaved` to `saving`** (s0b request 11): the chip says "Saving…" during the
   800 ms debounce.
5. **The conflict copy's original "reopens read-only beside it" via a banner action**: one tab holds one
   `projectStore`, so the original cannot be open next to the copy in the same tab. "Open the original" opens it
   in a new browser tab, where it is read-only while another tab holds it (tested).
6. **`StartScreen` copy** (still the Step 0 stub until T8.2): the empty state said "Saving isn't switched on yet…"
   and the restore button "Available once projects are saved" — both false now; changed to "Your projects are
   saved in this browser as you work." and "Coming soon: restore a project from the projects folder or a backup".
7. **A save never refuses a missing stored document** (deleted in another tab): it writes it again (rev =
   base + 1). Never losing the open tab's work wins over the deletion; a banner tells the user.
8. **A stored document of a newer format version is a conflict** for `save` (never overwritten) and `open`
   throws `MigrationError('newer-version')`.
9. **`remove(id)` deletes the document and its snapshots, never assets** (GC removes them after 7 days if
   nothing names them), and refuses a project another tab is editing (`ProjectLockedError`).
10. **Asset GC is global**, by reference, not by key prefix: conflict and imported copies share the original's
    keys (`<originalId>/<sha>`, s0b request 10), so a prefix says nothing about who uses an asset. References are
    every `<id>/<sha256>` string in every project and snapshot, followed through JSON assets (a model revision's
    `meshAssets`, s0b request 4). The delete transaction re-reads the references and deletes nothing that round
    if a document names a key the first pass did not see.
11. **Without `navigator.locks`** (an insecure context such as a LAN IP over http) the app uses an in-tab lock
    manager: compare-and-swap still prevents overwrites; only the read-only mode is missing there.
12. **The unload journal** (not in the spec): an IndexedDB save started in `beforeunload`/`pagehide` often does
    not land before the page goes (review finding 1: an edit made within the 800 ms debounce was lost on 2 of 4
    reloads and 4 of 4 navigations in Chromium; with an immediately accepted prompt still on 6 of 12 reloads).
    So the unsaved document is also written synchronously to `localStorage` and replayed at the next start under
    the compare-and-swap rules (see `journal.ts`). Measured after the change: 12 of 12 runs of "edit, reload at
    once" and "edit, close at once" kept the edit, with no prompt. `beforeunload` asks only when the journal could
    not be written, a save is failing, or storage is closed. Assets are not journaled (blobs cannot be read
    synchronously).
13. **A hand-over happens only when everything is saved.** The holder's flush must finish within 4 s and leave
    nothing unsaved; otherwise it keeps the project and the asker times out and may Take over (whose rev bump
    makes the holder's late save a copy). So "Your changes were saved first." is always true. A holder whose
    lock went away during the flush (its changes became a copy) answers `released` at once.
14. **A conflict found while leaving** (for another project or the library) does not navigate to the copy: a toast
    names the copy instead.
15. **Dev hot updates**: the app's session is kept on `globalThis`, so re-running `useAutosave.ts` or
    `persistence.ts` reuses it instead of starting a second session on the same store.


### T8.2

16. **Where backups go.** §5.5.4 names `Backups/` next to `projects/`. For a folder named `projects` (the default
    folder) that is `<parent>/Backups`; any other folder (a test's `mkdtemp`, whose parent is the shared temp folder)
    keeps them inside itself, `<folder>/_backups` — an id can never be `_backups` (`isFolderProjectId`).
17. **Protocol additions** (for the client and the restore dialog): `GET /__projects/<id>/assets` (the sha list: one
    request instead of a `HEAD` per asset, and no 404 per missing asset — Chromium logs every 4xx as a console error),
    `GET /__backups`, `GET /__backups/<backup>/<id>/doc`, `GET /__backups/assets/<sha>`; the list also carries name,
    mode, bytes and the folder status (path, free space, level, message, last backup run). `PUT …/doc` is a
    compare-and-swap on the folder (`x-cpg-base-sha256`; `none` = must not exist; absent = unconditional).
    Expected outcomes answer **200 with `ok` in the body** (a conflict, an existing asset); 4xx/5xx only for broken
    requests, so no console error in normal use.
18. **Folder-safe ids** `^[A-Za-z0-9][A-Za-z0-9._-]{0,199}$`: app ids (UUIDs) always pass; an imported file's odd id
    (e.g. with `:`) is not mirrored and is listed in `MirrorState.unsupported`, rather than escaping into a path.
19. **The protected folder is wider than "the default folder"**: also any folder inside it or containing it
    (`~/Documents`, `~`), its iCloud Drive path, other spellings (case, trailing `/`, `~`, NFC) and symlinks into it.
    A checkout with no `.git` counts as "not master". The decision is a pure string check first: a refused folder is
    never touched.
20. **Backups**: no backup while the folder holds no project (`empty`; an e2e temp folder would otherwise get one on
    every start); a backup is written into `.<name>.partial-*` and renamed into place, so it appears complete or not
    at all; `Backups/deleted/` is never pruned and not counted in the cap (deleted projects stay until the owner
    deletes them by hand); shared-asset GC is skipped while a folder with a backup's name has no readable manifest
    (its assets are unknown); retention also runs when the backup is skipped as unchanged (a lowered cap applies).
21. **`HEAD /__projects` probe and `/__convert` in vitest**: the plugin does nothing in vitest's own Vite server
    (mode `test`) — no routes are served there, and every `npm test` printed "Folder mirror off" otherwise.
22. **HEIF sniffing in the plugin** duplicates `sniffHeifBrand` of `workers/decode.ts` (S0) in 15 lines, tested equal on
    a sample set: importing the browser module into the Vite config pulled extensionless imports that Vite's native
    config loader warns about on every start.
23. **Sync details**: pushes and reconciles of all tabs run under the Web Lock `cpg-mirror` (two tabs pushing one
    project after each other otherwise produced a false two-sided copy in a test). A first sync where the folder
    already has the project with the **same content** (another serialization, a reset browser) adopts it; with other
    content it keeps both. A local rev **older** than the sync base is offered the folder version. "Changed in the
    folder" is an offer (notice + restore dialog: **Load folder version** — the browser's version is snapshotted
    first — or **Keep both**); a two-sided edit keeps both at once and says so in a toast. A folder doc of a newer
    format is never overwritten or loaded (the push fails with the "update the app" message). Projects in "Recently
    deleted" stay mirrored; deleting one for good sends `DELETE` (→ `Backups/deleted/`).
24. **A project in "Recently deleted" does not open from its link** (the shell shows "This project isn't here"); the
    library offers Restore. Purge runs at start-up only.
25. **Start-up chores wait ≤ 2 s**: purge and GC run after the journal and before any open, but an open waits at most
    2 s for them (a large library's GC reads every snapshot); at start-up this tab holds nothing GC could take.
    Without `navigator.locks.query` the round is skipped (`no-lock-query`).
26. **Preferences are persisted** (T8 per the appStore header, though not listed for T8.2): `settings` key `prefs`,
    plus a synchronous `localStorage` copy (`cpg.prefs.prefs`) written first — an IndexedDB write started just
    before a reload may never land (the smoke test's "theme survives a reload" failed without it) — which wins at
    start. The first start keeps what the page started with (the theme `main.tsx` read back).
27. **Free-space warnings and the folder path are shown in the library** (a banner above the cards; the restore
    dialog's folder panel) — there is no Settings screen yet (request 13).
28. **Same-name cards** get " · #abcd" (the id's first 4 characters) after the name — `ProjectGrid` (S0) has no slot
    for a second line; the card's buttons keep the real name in their accessible names.
29. **The mirror is on in e2e** (the e2e server's temp folder is not protected), so `e2e/smoke.spec.ts:82` expecting
    "Folder mirror off" fails (request 10).
30. **An edit takes a project out of "Recently deleted"** (review finding 1): `save` deletes `trash:<id>` in its
    transaction. A tab that had the project open (or "Edit here instead", Take over, a journal replay) could
    otherwise keep working on a project that is then purged with the new work. A tab with the project open gets
    a banner when another tab deletes it ("Any change you make here brings it back").
31. **Tombstones for the folder** (review finding 2): `remove` leaves `gone:<id>` with the last synced hash; the
    reconcile moves a folder copy away (`DELETE` → `Backups/deleted/`) only if it still has that hash, else offers it
    — so a project purged before the mirror started never comes back as an offer, and one changed elsewhere is
    never moved away.
32. **The reconcile never stops at one bad project** (review finding 3): each project's step is isolated; problems
    (a damaged or newer-format folder doc) are collected into `lastError` (status `error`) while the others are
    pushed and offered. A local project missing from the folder is pushed again even when its sync base says
    "up to date" (deleted from the folder by another browser or by hand).
33. **Restore-dialog results are shown inside the dialog** and take the focus (review findings 8–9: toasts render
    under the modal's backdrop, and a row that goes away dropped the focus to `<body>`); "Load folder version" asks
    first, inline. Focus also moves to the restored card after a restore from "Recently deleted", to the next row
    after "Delete for good", and to the restore button when the dialog's opener is gone.
34. **Plugin hardening** (review findings 4–6): `/System/Volumes/Data/…` (the macOS firmlink spelling) folds to `/…`;
    the account's own home (`os.userInfo().homedir`) is protected even when `$HOME` points elsewhere; start-up runs
    of one backups folder are chained on `globalThis` (a Vite restart re-evaluates the plugin while the old store may
    still be backing up); an asset deleted under a running backup is left out of its manifest instead of failing
    it; shared-asset GC waits while a `.partial-` backup exists; skipping GC for an unreadable manifest is logged.

|---|---|
| §5.5.3 "same id and identical content" | The documents compared by canonical JSON without `rev` and `updatedAt`, and every asset of the file already stored. |
